# claudmagi — 디자인 노트

참고 영상: `~/Downloads/HRxKPCOaoAAn4b7.mp4` (854×480, 15fps, 15.4s). 프레임 추출 관찰 결과.

## 전체 인상
- 참고 영상의 배경은 선명한 주황(약 `#F04A0E`)이지만, claudmagi는 배경을 흰색으로 쓰고 선 위를 흐르는 작은 패킷을 그 주황으로 칠한다(#16).
- PCB 트레이스 / 지하철 노선도 느낌의 얇은 검은 선들이 수평 → 45° 대각선 → 수평으로 흐른다.
  대각선 구간은 서로 평행하게 묶여 "밴드"를 이룬다.
- 선 위에 검은 둥근 사각형 "칩"이 얹혀 있고 라벨은 민트 그린(약 `#3BE38A`) 대문자 고정폭 글꼴.
  대각선 위의 칩은 45° 회전, 수평 구간의 칩은 수평.
- 선을 따라 작은 점(패킷)이 이동한다 — claudmagi에서는 주황색.

## 상태 표현
| 상태 | 표현 |
|------|------|
| 작업 중 (연결) | 검은 칩 + 녹색 라벨, 선이 칩을 관통. 다크 테마에서는 흰 칩 + 짙은 녹색 라벨(#32) |
| 서브에이전트 | 부모 세션 칩 오른쪽, 같은 선 위에 더 작은 칩(높이 16)으로 사슬처럼 이어짐(#12, #13). 실행 중이면 연결, 끝나면 분리됐다가 45초 뒤 사라짐 |
| 입력 필요 / 완료 (세션, 분리) | 선이 느슨한 케이블 모양(S자 파형)으로 늘어진 뒤 홈(notch)이 파인 검은 소켓 블록에서 끝남. 칩은 소켓에서 떨어져 나가 있다. 흰색·다크 테마에서 **입력 필요는 주황 칩 + 검은 라벨**, **완료(idle)는 어두운 적갈색 칩 + 앰버 라벨**(#50) — 기다리는 쪽이 더 눈에 띈다. 오렌지 테마는 주황 칩이 배경에 묻히므로 입력 필요 적갈 + 앰버, idle은 한 단계 더 어두운 적갈 + 흐린 앰버 |
| 완료 (서브에이전트, 제자리) | 서브에이전트는 분리되지 않는다: 선이 그대로 관통한 채 바탕만 idle 색으로 가라앉고 높이가 16 → 12로 줄어든다. 45초 뒤 페이드아웃 (#53) |
| Linear 노드 (왼쪽 끝) | 세션의 Linear 이슈. 보드 **왼쪽 끝에 붙어** 있고 레인은 이 노드의 오른쪽 모서리에서 시작한다 — 작업이 티켓에서 나온다는 뜻. 상태(`state.type`)를 색으로: backlog·미조회 흐린 테두리 · todo 잉크 테두리 · **진행 중 앰버 채움** · **완료 검정 채움** · 취소 흐린 테두리. 클릭하면 **Linear 데스크톱 앱**으로 (#57, #58, #60) |
| PR 커넥터 (오른쪽 끝) | 세션에 연결된 GitHub PR들. **하나의 티켓에 PR이 여러 개일 수 있어** 오른쪽 끝 기준으로 최신이 바깥쪽이 되게 가로로 이어 붙이고, 체인이 210px를 넘으면 오래된 것부터 `+n` 배지로 접는다. 트레이스는 체인의 가장 왼쪽 노드에서 끊긴다 (#63). 보드 **오른쪽 끝에 붙어** 한 열로 정렬되고, 트레이스가 왼쪽 모서리로 들어가 거기서 끊긴다 — 작업이 보드 밖으로 나간다는 뜻. 핀 없이 **몸통 색이 상태 전부**를 나타낸다: draft 잉크 테두리 · **open 녹색 테두리** · **체크 실패 오렌지 채움** · **merged 보라 채움**(테마별 `merged`/`on_merged`: 흰 보드 `#8250DF`, 주황 `#4B298C`, dark `#A371F7` — 칩의 검정을 나눠 쓰던 걸 자기 색으로 뻐냈다, 같은 레인 위 세션 칩과 한눈에 갈리도록. #82) · closed 흐린 테두리. 테두리는 진행 중, 채움은 결판난 것. **approved 는 `Look` 에 없다** — 승인은 상태·CI 와 **직교**라 enum 에 넣으면 고를 필요 없는 선택을 강요한다. `Look` 은 GitHub 상태 + 체크(draft·open·failing·merged·closed)만 맡고, 승인은 `Pr::signed_off()` 로 **그 위에 얹는 체크**다 — CI 가 돌 때 노란 테두리를 덧씌우는 것과 같은 층(#62). approved+failing, approved+draft, approved+merged 가 전부 제 모습대로 읽힌다(전에는 `look()` 이 Failing 을 골라 승인이 통째로 사라졌다). **머지도 승인이다** — 사인오프 없이 착륙하는 PR 은 없으므로 merged 는 `reviewDecision` 이 뭐라 하든 체크를 단다. 체크는 **그린다**: 보드 라벨은 D-DIN 외곽선에서 나오는데 그 페이스에 체크 글리프가 없어 `✓` 은 `?` 로 떨어진다(`Shape::Stroke` 3점 폴리라인). 커넥터는 체크 자리만큼 넓어지고 번호가 그만큼 오른쪽으로 밀려 둘이 가운데 정렬을 유지한다. merged·closed 에는 안 붙는다 — 거기서 승인은 이력이지 할 일이 아니다. (#116) **CI가 돌고 있으면 테두리를 노란색(1.7px)으로** 덮어쓴다 — 상태가 아니라 겹쳐 그리는 층이라 채워진 커넥터 위에도 보인다(재실행 중인 approved 등). 클릭하면 PR이 열린다 (#56, #57, #58, #62) |
| 레인의 굵기와 색 | **굵기 = 지금 일어나는 일, 색 = 끝난 일**이고 둘은 독립이다. 레인의 세션이 working 이면 굵게(1.6 → 2.9). Linear가 완료 + PR이 **하나 이상 머지되고 나머지도 전부 머지/클로즈**(진행 중인 게 없음) + 세션이 idle 이면 초록(`palette.done`: 흰 보드 `#148B51`, 주황 `#0E5132`, dark `#3BE38A` — 칩 위가 아니라 보드 위 머리카락이라 더 진하게 잡았다). working 판정은 레인의 첫 칩이 아니라 **세션 칩을 찾아서** 한다 — 서브에이전트가 앞서면 놓쳐서 패킷 속도까지 같이 틀려 있었다 (#61, #84) |

## 클라우드 세션 (#120)

- **이 맥에 아무것도 안 남는다**: 데스크톱 앱·iOS·스케줄에서 띄운 세션은 Anthropic 컨테이너에서 돈다 — 프로세스도, `~/.claude/sessions/<pid>.json` 레코드도, **트랜스크립트조차** 없다. 레지스트리를 쓰는 건 Claude Code 코어가 아니라 **CLI 엔트리포인트**라서, 앱이 Claude Code 를 제 Node 프로세스 안에서 돌려도 레지스트리에는 안 들어온다. 디스크로는 원리적으로 못 본다.
- **그래서 API 로 읽는다**: `GET https://api.anthropic.com/v1/code/sessions?limit=60&include_trigger_sessions=true`, `Authorization: Bearer <토큰>` — 데스크톱 앱이 목록을 받아오는 그 엔드포인트이고, 토큰은 `usage.rs` 가 이미 로그인 키체인에서 꺼내 쓰는 바로 그것이다(#48). HTTP 클라이언트는 링크 안 하고 `curl` 로 나간다.
- **답이 로컬 레지스트리보다 낫다**: `connection_status`(컨테이너가 살아있나) · `worker_status`(턴이 돌고 있나) · `unread`(사람이 봤나) · `external_metadata.post_turn_summary.needs_action`·`.status_detail` · `config.outcomes[].git_info.repo` · `current_branches`. **전부 보고된 값이고 추측이 아니다** — 그게 보드에 올릴 값어치의 근거다.
- **phase 매핑**: 턴이 돌면 Working. 턴 사이에는 '누가 기다리는가' 가 질문이고 둘이 그걸 말한다 — 요약이 할 일을 지목했거나(`needs_action`), 끝났는데 **사람이 아직 안 봤거나**(`unread`). 클라우드 작업은 아무도 안 볼 때 끝나므로 두 번째가 흔하고, 그게 바로 보드가 있는 이유다. 둘 다 아니면 Idle.
- **루틴은 안 띄운다**(#125): 스케줄이 띄운 세션(`trigger_id` 가 있는 것)은 사람이 기다리는 일이 아니다. `include_trigger_sessions=false` 로 **서버에서** 빠진다 — 이 계정 기준 19개 중 12개가 그것이었다. `parse` 도 `trigger_id` 가 있으면 버린다: 파라미터 이름이 바뀌는 날 루틴이 조용히 돌아오지 않도록.
- **아카이브한 건 치운다**(#136): `status` 가 `archived` 면 버린다. 사람이 '이건 끝났다' 고 **직접 말한 것**이라, 보드가 스스로 따져볼 수 있는 어떤 신호보다 세다 — 컨테이너가 떠 있어도, 방금 턴이 돌고 있어도 치운다. 아래 12시간 규칙보다 먼저 본다. `active` 와 `archived` 말고는 본 적이 없지만 **모르는 값은 건드리지 않는다**: 새 상태 하나가 조용히 보드를 비우면 안 된다. 실제로 이 계정에서는 12시간 창을 통과하던 단 하나가 아카이브된 그 세션이었다.
- **무엇을 보여줄까**: 보드는 지금 돌아가는 것을 보여주는 물건인데 클라우드는 몇 주치 실행을 기억한다. `connected` 면 시계와 무관하게 현재. 아니면 `last_event_at` 이 `RECENT`(12시간) 안이어야 한다 — 점심에 끝난 일은 아직 볼 거리지만 지난주 크론은 아니다.
- **PR 은 문장에서 뽑는다**: 트랜스크립트가 없으니 `pr.rs` 가 훑을 게 없는데, 요약문은 사람 읽으라고 쓰인 거라 번호를 소리내어 말한다 — "PR #9312 E2E passed (194/194); awaiting reviewer approval". 거기에 `git_info.repo` 를 붙이면 온전한 `PrRef` 라, 그걸 `pr::Tracker` 에 넘겨 `gh` 가 상태를 채운다. 못 채우면 `prs_unanswered` 로 남아 보드가 그렇다고 말한다(#112).
- **자리**: `Seat { host: "cloud", window: repo }` — 같은 저장소의 세션이 한 클러스터가 된다(`cloud-tab:<repo>`, 라벨은 "cloud <repo>"). 띄울 창이 없으니 클릭은 `https://claude.ai/code/<id>` 를 연다(웹·데스크톱 앱 어느 쪽이든 받는다). 환경변수로는 아무것도 줍지 않는다 — 여기 프로세스가 없으므로.
- **캐시**: 30초 TTL, 실패하면 5초 뒤 재시도하되 **이전 목록을 버리지 않는다** — 네트워크가 한 번 흔들렸다고 보드가 비는 건 조금 낡은 것보다 나쁘다(#59 와 같은 규칙).
## 호스트 레이어 (#118)

- **레지스트리는 터미널 것이 아니다**: `~/.claude/sessions/<pid>.json` 은 Claude Code 가 쓴다 — 어디서 돌든 쓴다. 데스크톱 앱(`/Applications/Claude.app`)도 **같은 디렉터리를 읽는** 쪽이다(번들 안에 `sessionsDirPath()` → `/^\d+\.json$/` 스캔, 실패 메시지가 "Claude Code's session registry"). 레코드를 쓰는 건 `claude` 프로세스 자신이다. 그래서 **데스크톱 앱 세션은 이미 보드에 뜬다** — 터미널이 없을 뿐이다.
- **터미널이 더하는 건 자리(seat)다**: 어느 앱의 어느 창에 앉아 있는가(같은 창이면 한 클러스터, #41)와 클릭했을 때 거기로 돌아가는 법. 그게 `host/` 의 `Host` 트레이트다 — `seat(env)` 가 환경변수로 세션을 **주워가고**(먼저 주운 호스트가 임자), `windows(handles)` 가 환경이 안 알려준 창을 스냅샷당 한 번에 묻고, `focus(seat)` 가 데려간다.
- **호스트마다 성격이 전혀 다르다**: Warp 는 탭을 제 DB 에 들고 있어 Full Disk Access 가 필요하다(#67, #69) — `windows()` 가 그 sqlite/`warpctrl` 왕복을 맡는다. Orca 는 **환경변수에 탭을 그대로 넣는다**(`ORCA_TERMINAL_HANDLE`·`ORCA_TAB_ID`·`ORCA_PANE_KEY`·`ORCA_WORKTREE_ID`) — Orca 소스의 주석대로 "per-PTY 라 프로세스 수명 동안 안정" 이다. 우리가 이미 읽는 `proc_env(pid)` 에 다 있으므로 **권한도 왕복도 0** 이고, 돌아가기는 `orca terminal switch --terminal <handle>`(티켓 조회가 쓰는 그 CLI). 데스크톱 앱은 아무 표시도 안 남겨 한 그룹에 모이고, 돌아가기는 앱을 띄우는 것뿐이다.
- **그룹 키는 모양으로 읽는다**: `{host}-tab:{window}` / `{host}:{handle}` / `term:{prog}` / `desktop`. `group_label()` 은 호스트 이름 목록이 아니라 이 **모양**에 대고 쓰여 있어, 호스트를 더해도 손댈 곳이 없다. 창을 모르면 **seat 단위로 쪼갠다** — 탭이 아직 안 왔다고 같은 Warp 의 네 pane 을 한 덩어리로 묶으면 레이아웃이 틀린 채 떴다가 답이 올 때 전부 밀린다(#59).
- **안 한 것**: Claude.app 에 `claude://code/continue?session=` · `claude://resume?session=<uuid>` 딥링크가 있지만 resume 은 CLI 세션을 앱으로 **import** 하는 것이지 돌아가기가 아니다. 앱이 호스팅하는 세션을 실제로 보기 전까지는 앱을 띄우는 게 정직하다.
## claudmagi 매핑
- 세션 1개 = 칩 1개. 라벨은 `~/.claude/sessions/<pid>.json`의 `name` 대문자.
- 파킹된 백그라운드 잡(`kind: "bg"`)은 자기 칩을 갖지 않고 부모 세션의 트레이스에 서브에이전트처럼 매달린다 — 부모가 띄운 프로세스라 Warp 환경변수를 그대로 물려받아, 그냥 두면 같은 pane을 가리키는 칩이 둘이 된다. 잡의 `jobId`와 부모의 `parkedJobId`로 짝을 찾고(`fold_parked_jobs`), 잡의 PR·티켓은 부모 레인으로 합친다. 라벨은 `/jobs` 핸들, 연결 여부는 세션과 같은 기준(`status == busy`). 부모가 사라진 잡은 자기 칩을 유지한다 — 그 pane을 가리키는 게 더는 없다. (#68)
- `status == busy` 이고 `waitingFor` 없음 → 연결 상태.
- `waitingFor` 있음(권한/다이얼로그) 또는 `tempo/state == blocked` → 분리 + 앰버(입력 필요).

## 허니콤 뷰 (#86)

설정 `VIEW` 에서 `CIRCUIT` 과 고를 수 있는 두 번째 뷰. 같은 세션을 트레이스 위 칩이 아니라 세로로 스크롤하는 육각 격자에 놓는다. 그림은 보드와 같은 `Shape` 목록을 거치므로 화면과 `--svg --view comb` 양쪽에 똑같이 나온다.

- **flat-top**(#132): 평평한 면이 위아래, 꼭짓점이 좌우. `axial(q, row) = (1.5r·q, r√3·(row + q/2))` — `q` 가 열이고 폭의 3/4씩 가며, 열마다 반 행씩 내려가 서로 맞물린다. `corners` 는 정동(0°)에서 시계방향 `60i`. `half_w = r`, `half_h = √3r/2` 로, pointy-top 때와 가로세로가 뒤집혔다. **상수 폭 구간이 없어졌다**: pointy-top 은 `|y| ≤ R/2` 에서 폭이 일정했지만 flat-top 은 한가운데 한 줄이 가장 넓고 위아래로 `1/√3` 씩 좁아진다(`room_at`) — 가운데 세션 행은 더 넓어지고 위아래 티켓·PR 행은 좁아져 라벨이 조금 더 잘린다. 세션 베드는 사각형을 버리고 **셀 모양으로 깎은 육각 슬래브**다(#133) — 위아래는 평평하고 좌우는 셀과 **같은 자리에서 뾰족해진다**. 사각형은 flat-top 의 좌우 꼭짓점을 비워두고, 그 꼭짓점까지 닿을 만큼 넓힌 사각형은 제 모서리가 육각형 밖으로 나간다 — 그래서 여섯 변이다. 벽 두께(`WALL`)만큼 안으로 들어가 테두리를 덮지 않는다. 면→이웃 방향(`FACE_DIRS`)은 이제 `DIRS` 와 그대로 일치한다(pointy-top 에서는 한 칸 어긋나 있었다). 격자는 **행이 아니라 열로** 만든다 — `x` 가 `q` 에만 의존하므로 열이 보드를 따라 내려가는 직선이다. 클러스터 배치 스캔도 인덱스가 아니라 **픽셀 좌표로 정렬**한다: `row` 가 이제 대각선이라 `(row, q)` 순서로는 어디에 앉는지 알 수 없다(#121 의 '처음 맞는 자리' 가 **화면 가운데에서 가장 가까운 자리**를 뜻하려면 필요하다, #138).

- **격자가 곧 화면**: 빈 칸도 전부 그린다(`ink@18%`). 돌고 있는 것의 모양을 돌지 않는 것의 모양에 대고 읽게 하려는 것. **항목이 하나도 없어도 격자는 서 있고**, 도착 전인 칸도 옅은 육각으로 남는다 — 파도는 구멍을 뚫는 게 아니라 채워 넣는다. (#102)
- **테두리만, 셀끼리는 띄어진다**: 정육각형의 변을 `d` 만큼 안으로 밀면 외접반지름은 `2d/√3` 줄어든다. 각 셀을 `GAP/√3` 만큼 줄여 이웃 변 사이가 `GAP`(7)이 되게 한다. 처음엔 이 간격을 테두리 두께(1.4)로 둥 놓았는데, 실제 크기에서는 안 보여 격자가 한 덩어리 라티스로 읽혔다. 서브그리드는 작으니 `SUB_GAP`(2.4)으로 더 붙인다. (#87)
- **워프 탭 = 클러스터**: 한 탭의 pane 들이 한 꽃(중심 + 링)에 앉는다. 꽃은 **화면 가운데에서 바깥으로** 놓인다(#138). 좌석은 **모두가 이웃 한 칸을 남기도록** 고른다(#109): 꽃을 바깥으로 훑되, 그 자리를 차지하면 누군가 서브에이전트 둘 곳이 없어지는 좌석은 건너뛴다 — 여섯이 링을 채우면 가운데가 갇히므로 일곱 번째는 한 칸 더 바깥으로 간다. 그래도 막히면 서브에이전트 칸은 링 3까지 넓혀 찾는다(#108).
- **셀 안은 위에서부터 Linear / Warp / 산출물(GitHub·아티팩트, #137)**: 순서가 고정이라 여러 셀을 세로로 훑으며 같은 줄끼리 비교할 수 있다. 없는 항목은 그리지 않는다. 라벨은 육각형 밖으로 나가지 않게 자른다(`row_box`): 육각형은 꼭짓점으로 갈수록 좁아지므로 행의 가운데가 아니라 **행의 바깥 모서리 높이**에서 쓸 수 있는 폭을 재고, 마크·간격·안쪽 여백을 물리고 남는 만큼만 남긴 뒤 … 를 붙인다. 한 글자도 안 들어가면 아예 안 쓴다. (#94)
- **한 클러스터의 셀이 맞닿은 벽은 이중 선**(#128): 안쪽으로 `SEAM` 들어간 선을 하나 더 긋는다. 간격은 **고르지 않고 선 두께에서 끌어낸다** — `SEAM = WALL × 3` 이라 **공백이 선의 두 배**다(#129, #130, #131). 넓은 보드에서 보기 좋게 고른 절대값은 좁은 보드에서 셀 속으로 너무 깊이 들어간다(셀은 줄어드는데 선은 안 줄어든다). 바깥을 향한 벽은 한 줄 그대로라, 클러스터가 한 덩어리로 읽히고 속은 솔기가 보인다. 인접 자체가 이미 '같은 클러스터' 를 말하지만(#121) 그걸 그림으로 말하는 쪽이다. 선은 통째로 안쪽 육각형(`corners(c, r, GAP + 2·SEAM)`)에서 떼어 온다 — 직접 평행이동하면 양 끝이 옆 벽을 넘는데, 이러면 자연히 짧아져 안쪽에 멎는다. 벽 `i` 의 이웃 방향은 `FACE_DIRS` 가 쥐고 있다(`corners` 가 위에서 시계방향이라 `DIRS` 를 한 칸 돌린 것) — **이게 틀려도 선 개수는 같아서** 엉뚱한 벽에 그어지는 게 유일하게 조용한 실패라, 그리드에 대고 따로 고정해뒀다.
- **클러스터 배치는 그리드에 직접 묻는다**(#121): 꽃마다 **화면 가운데에서 가까운 순으로 훑어 처음 들어맞는 칸**을 쓴다(#138) — 전부 화면 안이고, 이미 놓인 꽃의 칸이나 **그 옆칸**이 아닌 자리. 전에는 픽셀 `x` 를 걸어가며 가장 가까운 셀로 스냅하고, 가장자리를 넘으면 열 단위로 밀어넣었다 — 그 보정들이 전부 '간격을 벌리려던 단계' **뒤에** 좌석을 움직이고, `seat_cluster` 도 제 사정으로 또 움직인다(#109). **폭이 좁아지면 보폭은 작고 보정은 커서 다른 그룹끼리 벽을 공유**했고, 그러면 두 클러스터가 하나로 읽힌다. 비용은 꽃 모양을 한 번만 만들고(`seat_cluster` 는 중심 기준 오프셋이라 위치와 무관하다) 점유를 `HashSet` 으로 보게 해서 잡았다 — 클러스터 12×7 기준 프레임당 5.83ms → 0.27ms. `Cell` 이 제 축좌표를 들고 다니므로 픽셀 역함수(`cell_at`)는 없앴다.
- **가운데부터 놓는다**(#138): 후보 칸은 세 가지로 줄세운다 — ① **화면 안인가**(격자에는 위 끝이 있어 아무것도 그 위로 못 나가지만 아래 끝은 없다 — 보드가 스크롤하므로. 이게 없으면 첫 줄이 비어 있는데도 클러스터가 화면 밖으로 내려간다), ② **전체의 무게중심이 화면 가운데에 얼마나 가까운가**, ③ 그 꽃 자신이 가운데에서 얼마나 가까운가. ②가 핵심이다: 둘째 클러스터는 첫째에게 가운데를 내줘야 하는데, 자기 거리만 보면 그다음도 **같은 쪽으로** 쏠려 가운데의 한 귀퉁이에 집이 지어진다(셋이면 1.00r → 0.50r). 꽃의 위치는 **좌석들의 평균**으로 잰다 — 앵커 칸은 꽃의 꼭대기라(#109 가 아래로 자란다) 그걸로 재면 제 키의 절반만큼 위에 걸린다. 대가: 전체를 다 놓고 **통째로 가운데로 옮기는** 방식이 아니라서 짝수로 갈라지는 배치는 반 칸씩 치우치고, 빽빽한 보드에서는 좌상단부터 채우던 때보다 **한 클러스터가 접히는 선 아래로 밀릴 수 있다**(가운데 꽃이 화면을 세로 띠로 갈라 폭 2열짜리 꽃이 들어갈 자리가 없어진다). 통째로 옮기는 쪽을 안 고른 이유는 그러면 세션 하나가 끝날 때마다 **보드 전체가 한 칸씩 뛰고**, 정작 빽빽한 보드에서는 옮길 여지가 없어 아무것도 달라지지 않기 때문이다. 높이는 창 높이가 아니라 **보이는 높이**(상태바를 뺀)를 받는다.
- **서브에이전트는 옆칸, 셀을 일곱으로 나눈 서브셀에**: 부모 셀에서 넘치지 않고 바로 옆 빈 셀을 하나 차지하고, 거기에는 **큰 육각을 그리지 않는다**(#97). 그 셀은 **가운데 하나 + 링 여섯, 모두 일곱 개의 서브셀**로 나뉘고 서브에이전트가 그중 한 자리에 앉는다(#105). 일곱은 몇 개가 찼든 크기가 같다 — 둘이면 큰 육각 둘이 아니라 일곱 중 둘이다. 링 `k` 는 세로로 `1.5k+1`, 가로로 `(k+0.5)·√3` 미니 반지름을 먹고 셀은 `R`·`(√3/2)R` 을 주므로 가로가 빡빡한 쪽이라 `R/(2k+1)` 이 나온다(일곱이면 `R/3`). 일곱을 넘으면 열아홉으로 더 잘게 나눈다. `Shape::Poly` 로 **보드의 칩 색**을 채우고(#96, #110 — 흰 보드면 검정, dark 보드면 흰색, 즉 그 보드에서 일하는 칩이 입는 색) 그 위에 보드 배경색으로 이름을 쓴다(#95). 끝난 서브에이전트는 같은 색을 보드 쪽으로 45% 물린 톤. 빈 칸을 찾을 때 **화면 안인지도 함께 본다**(#111): 가장자리 밖이나 첫 행 위의 칸은 아예 그려지지 않아, 거기로 보내면 자리를 못 찾은 것과 똑같이 사라진다. 아래쪽은 스크롤되므로 제한하지 않는다.
- **셀 안 세 줄은 각각 클릭 대상**: 세로 위치로 Linear/Warp/GitHub 밴드를 갈라(`hit_slot`), 각각 이슈·탭·PR 로 간다. 비어 있는 줄을 누르면 세션으로 떨어진다. Warp 줄은 셀 테두리와 같은 색을 **셀 안쪽 좌우 끝까지** 깔고 그 위에 보드 배경색으로 라벨을 쓴다(#91 — 가운데 줄은 육각형이 가장 넓고 양 옆이 수직인 지점이라, 반지름보다 낮은 띄는 몸통은 벽에만 닿고 구석을 안 넘는다) — 그래서 테두리 색은 알파가 아니라 불투명 값으로 만든다. (#89)
- **PR 이 여럿이면 GitHub 행은 목록을 떨군다**(#134): 셀은 `prs.last()` 하나만 그리므로 나머지는 보이지도, 닿지도 않았다. 누르면 그 셀이 아는 PR 전부가 카드로 내려온다 — 답을 받은 것과 **GitHub 이 답하지 않은 번호**(#112)를 번호 내림차순 한 줄로 합쳐서(`pr::rows`). 행 하나하나가 노드다: 보드가 그 PR 에 줄 몸통을 그대로 입고(#78) 팔레트 행과 같은 모양으로 선다. 하나뿐이면 종전대로 바로 열고, 하나도 없으면 셀로 떨어진다(`pr_press`). 여는 쪽은 **누를 때**다 — 메뉴가 열리는 시점이 그렇고, 보드에 닿는 다른 누름은 전부 목록을 닫는다(카드는 제 누름을 `stop_propagation` 으로 삼킨다). 자리는 행의 상자(`comb::slot_box` — 밴드의 **바깥 모서리 높이**에서 잰 폭이라 육각형을 안 넘는다) 아래, 상태바에 걸리면 위로. gpui 엘리먼트라 `--svg` 에는 안 나온다. 같은 이유로 보드 뷰의 PR 툴팁은 comb 에서 끈다 — 커넥터 위치가 허니콤과 무관해 아무것도 없는 자리에 떴다.
- **세션이 만든 클로드 아티팩트도 같은 줄에**(#137): 맨 아랫줄은 이제 PR 전용이 아니라 **그 일이 내놓은 것**의 줄이다(`Slot::Output`). 아티팩트는 세션이 claude.ai 에 발행한 페이지(before/after 리포트, 트래커, 덱)고, 나오는 곳은 PR·Linear 와 같은 **그 세션의 트랜스크립트**다(#56, #57). 다만 읽는 법이 다르다 — PR 은 사람이 쓴 문장 속에 **지나가듯 적히지만**, 아티팩트는 만든 도구가 제 줄에 대고 **선언한다**: `Published <파일> at https://claude.ai/artifact/<id> (Version 3, …)` 와 `Created a new Artifact at <url> … from the Artifact type <다른 url>`. 그래서 링크를 아무 데서나 줍지 않고 **그 두 문장만** 읽는다. 그 고정이 '이 세션이 **만든**' 것으로 목록을 한정한다 — 사람이 붙여넣은 링크, 읽기만 한 페이지, 남의 페이지에 올린 에셋, 그리고 둘째 문장이 뒤이어 말하는 **타입**(남이 발행한 페이지)이 전부 같은 URL 모양이다. 첫 주소만 집는다. 이름은 페이지 제 `<title>` — claude.ai 갤러리가 부르는 그 이름이고, 선언 줄에는 없으니 **발행된 파일에서 읽는다**(타입에서 만든 페이지는 파일이 없고 호출의 `title` 이 유일한 기록이라 그쪽을 먼저 본다). 파일이 치워졌으면 파일 이름(`index.html` 이면 그 폴더), 그것도 없으면 id — 이름을 모른다고 가리킬 값어치까지 없어지지는 않는다. 셀에서는 **PR 라벨 뒤에 창 마크**가 붙고, 둘 이상이면 개수가 따라붙는다(하나뿐일 때 `1` 은 소음이다). PR 이 아예 없으면 그 줄이 **아티팩트의 줄**이 되어 제 이름을 쓴다 — 있는 걸 못 보여주고 빈 줄로 두느니. 누르면 내려오는 목록은 #134 의 그 카드인데, 이제 PR(번호 내림차순) 다음에 페이지(새것부터)가 선다(`made::rows`). 셀에 네 번째 줄을 낼 자리가 없어서가 아니라, 둘 다 '**열어볼 것**' 이라 같은 줄이 맞다. ⌘K·⌘L 에도 같은 행이 선다 — 페이지는 번호가 아니라 **일의 이름**으로 불리므로 검색이 특히 값어치 있다. 클라우드 세션은 이 디스크에 트랜스크립트가 없어 아무것도 안 뜬다(#120).
- **PR 은 셀의 바닥을 칠한다**(#139): 아랫줄은 글자 색이 아니라 **바탕**으로 상태를 말한다 — `hit_slot` 이 셀을 가르는 그 선(0.21r, 즉 누름이 걸리는 경계)에서 시작해 셀의 아래 변까지, 육각형이 좁아지는 대로 좁아지는 사다리꼴(`output_bed`). 가운데 띠(#133)는 위아래로 셀이 더 있으니 띠일 수밖에 없지만 아랫줄은 밑에 아무것도 없어 남은 전부를 가진다 — 그래서 '두 번째 줄무늬' 가 아니라 **'아래부터 채워진 셀'** 로 읽힌다. **칠한 것은 눌리는 것과 같은 면적이다.** 글자는 세션 줄처럼 **보드 색**이라 바탕이 **불투명해야** 한다: `pr_color` 의 Draft(0.7)·Closed(0.35) 같은 비치는 색을 그냥 깔면 보드가 비쳐 대비가 무너진다. `theme::over(c, bg)` 가 '보드에 깔았을 때 보이는 그 색' 을 불투명하게 만들고(`with_alpha(c, 1.0)` 는 알파가 **곱**이라 아무 일도 안 한다 — 실제로 한 번 당했다), 그다음 `readable` 로 보드 대비 3.0을 맞춘다. **칠한 줄은 깜빡이지 않는다**: 테두리가 이미 빨갛게 뛰고 있고(#90), 보드 색 글자를 얹은 바탕이 페이드하면 글자가 같이 사라진다. 답 못 받은 번호(#112)와 페이지만 있는 줄(#137)은 칠할 상태가 없어 종전대로 둔다. **솔기(#128)는 이제 줄들 다음에 긋는다** — 두 베드가 제 밑의 벽까지 닿아서, 먼저 그으면 덮인다(가운데 띠도 전부터 덮고 있었다).
- **허니콤의 approved 도 체크로**(#116): 셀에는 채움이 없어 색이 전부인데 approved 와 open 은 같은 `text_on` 이었다 — 보드의 '테두리/채움' 문법이 여기엔 없으니 둘이 말 그대로 같은 픽셀이었다. 이제 GitHub 행은 `[마크][라벨][체크]` 이고 체크는 행의 캡 높이 0.95배(`CHECK_H`)로 그린다. 체크 자리는 **라벨의 몫에서 빼간다** — 마크와 같은 규칙이라(#94) 체크가 붙은 행은 셀 가장자리가 아니라 글자를 포기한다. 셀이 보여주는 PR 은 `prs.last()` 하나뿐이라, 데모에서 PR 체인(#63)을 approved 를 들고 있는 세션에 얹으면 그 look 이 comb 렌더에 영원히 안 나온다 — 체인을 빈 세션으로 옮겼다.
- **테두리 색은 셀 전체, 점멸은 기다리는 쪽만**: 색은 안에 사람 손이 필요한 게 있으면 alarm 으로 간다 — 세션이 직접 묻고 있거나(`NeedsUser`), PR 체크가 빨간 경우. 점멸은 다르게 나눈다(#100): **셀(테두리·Warp 행)이 뛰는 건 클로드가 물을 때뿐**이고, 빨간 체크는 GitHub 행이, 시작 안 된 이슈(Backlog·Todo)는 Linear 행이 **자기 줄만** 뛴다 — 할 일이 실제로 있는 자리에서 뛰게. 상태를 못 받아온 이슈(Orca 꺼짐)는 보드가 모르는 것이지 이슈가 부르는 게 아니라서 제외. (#90, #100) **GitHub 이 문제인 경우**도 GitHub 행이 뛴다(#112): 트랜스크립트가 이름 댄 PR 인데 `gh` 가 답을 안 주면, 번호만 알고 상태는 모르는 상태다 — 지금까지는 'PR 이 없음' 과 구분이 안 됐다. 그 경우 번호를 옅게 띄우고 점멸시킨다. 물어보기 전(아직 조회 중)은 여기 해당하지 않는다.
- **색**: 셀은 채움이 없어 모든 색이 보드 배경 위에 직접 놓인다. 칩 색은 제 칩 위에서만 읽히면 되는 값이라(주황 보드의 앰버는 주황 위에서 1.2:1) `theme::readable()` 이 배경 대비 3:1 을 넘을 때까지 잉크를 섞는다. 주황 보드는 여유가 없어 전부 잉크 근처로 수렴하는데, 그 보드가 원래 색이 아니라 형태로 말하는 방식과 같다.
- **열릴 때의 도착**: **첫 세션이 도착한 프레임**을 0 으로(켤 때는 첫 폴링 전까지 보드가 비어 있어, 퍼질 클러스터가 없는 채로 시계가 돌면 세션이 올 땐 이미 끝나 있다 #101)(넣었던 시점이 아니라 — comb 로 시작하면 첫 페인트 전에 다 끓난다, #93), 각 셀이 가장 가까운 세션에서 몇 칸 떨어졌는지(`Cell.wave`)를 순서로 때서 들어온다. 한 링당 `WAVE_STEP`(0.07s) 기다렸다 `WAVE_FADE`(0.5s)에 걸쳐 불투명해진다. 클러스터가 먼저 서고 빈 들판이 그 밖으로 번진다. `--wave <초>` 로 중간 프레임을 뽑을 수 있다. (#92)
- **스크롤**: 격자의 실제 높이로 `content_bottom` 을 잡는다. 클릭은 셀의 내접원으로 히트테스트해 그 세션의 Warp 탭으로 간다.

## 메타볼 뷰 (#140)

- **같은 자리, 녹은 셀**: 배치는 허니콤 것을 그대로 쓴다(`comb::lay_out`) — 한 창의 pane 들이 한 꽃, 클러스터 사이엔 빈 칸 한 줄(#121), 가운데부터 바깥으로(#138). 바뀌는 건 **몸통을 그리는 법**뿐이라 스크롤·히트테스트·슬롯 누름·PR 드랍다운·⌘K·⌘L 이 전부 그대로 돈다(`BoardView::seated()`). `src/render/blob.rs`.
- **필드**: 세션 하나가 공 하나. Wyvill 폴오프 `(1−d²)³` 를 쓰고 **반경 1.9r**, 레벨 0.5 에서 면을 딴다. 이 두 수는 취향이 아니라 **자리가 정한다** — 클러스터 동료는 `√3·r`(셀 한 칸) 떨어져 있고 남은 **절대 3r 안쪽으로 못 온다**(#121 의 빈 줄). 1.9r 이면 앞의 쌍은 중점에서 레벨의 두 배가 되어 **한 덩어리**가 되고, 뒤의 쌍은 폴오프가 반경 밖에서 **정확히 0** 이라 서로를 아예 모른다(그래서 클러스터마다 제 격자만 샘플링하면 된다). 혼자인 공은 반지름 `0.86r` — 허니콤 셀의 내접원과 같다. 세 줄이 그대로 들어간다는 뜻이다.
- **한 몸 안에서도 제 땅**: 점은 **가장 세게 당기는 공**의 것이다. 패치 = `min(필드−레벨, 내 당김 − 2등 당김)` 의 등고선 — `min` 은 두 영역을 교집합하면서 행진할 면을 남기는 유일한 수단이고, 이게 있어 **붙어버린 클러스터도 '여기는 누구냐' 에 색으로 답한다**. 샘플마다 합·1등·2등·주인만 들고 있으면 공이 몇이든 배열 넷으로 끝난다.
- **이음매 한 올**: 패치 테두리를 **보드 색**으로 한 줄 긋는다 — 바깥에서는 보드 위에 보드라 안 보이고, 패치 사이에서는 허니콤이 셀 사이에 두던 그 틈이 된다(상태가 같은 두 세션이 한 색으로 녹아 하나로 읽히는 걸 막는다). 세 패치가 만나는 점과 몸통 가장자리에서 각 패치의 윤곽이 샘플 몇 분의 일만큼 어긋나므로, 땅을 `BLEED` 만큼 키워 **겹치게** 한다 — 격자로는 못 고치고, 비는 것보다 겹치는 게 낫다.
- **PR 은 몸통의 바닥**(#139 를 그대로 옮김): 패치를 `y ≥ 누름 경계선` 과 교집합해서 칠한다. 같은 `min` 한 번 더.
- **줄**: 허니콤의 `slots`/`row_box_in`/`row_shapes` 를 **그대로 쓴다**(#140 에서 comb.rs 에서 뽑아냈다). 다른 건 글자가 앉을 폭을 육각형이 아니라 **원의 현**으로 잰다는 것뿐. 색은 보드가 아니라 **제 몸통 위에서** 읽혀야 해서 `legible(c, on, pal)` 이 밝은 쪽/어두운 쪽 중 대비가 사는 쪽으로 섞는다(`on=pal.bg` 면 종전 comb 와 같은 값).
- **도착**: 알파가 아니라 **반경이 자란다** — 레벨 아래의 공은 작은 공이 아니라 없는 공이라, 무게를 키우면 제 도착의 절반 지점에서 몸통이 **튀어나온다**. 반경을 키우면 공이 자라다 서로 붙는다(#92 의 파도를 그대로 탄다).
- **빈 칸은 점**: 격자는 이 뷰의 가구다(#102). 벽이 사라진 자리에 남는 것이 점이고, 파도도 같이 탄다.
- **비용**: 프레임당 0.56ms(릴리스, 12세션 6클러스터 1280×800. 허니콤은 0.02ms). 공마다 **제 반경 안의 창**만 행진하고(클러스터 전체를 돌면 클러스터의 제곱이다), 교차점은 **걸을 때 계산**하며(격자 전 변을 들고 있으면 프레임당 수 MB), 바닥은 같은 샘플을 다시 쓴다. 샘플 간격 `STEP=0.07r` 은 품질/비용의 타협점 — 0.055r 은 0.70ms, 0.1r 은 0.19ms 인데 1x 에서는 구분이 안 간다.

## 치수(디자인 단위)
- 기준 크기 980×620. 창이 커져도 자동 확대는 하지 않고(#19) 레인과 스트라이프를 더 채운다. 크기는 사용자 배율(⌘+/⌘-/⌘0, ⌘+휠, 상태바 −/+)로만 0.5~3배 조절한다(#18).
- 레인은 두 줄씩 짝: 짝 안 간격 22, 짝 사이 추가 간격 24(#14, #29, #31, #35, #39). 선 굵기 1.6, 대각선 낙차 128, 모서리 반경 8
- 레인은 하나의 계단: 레인 i는 폭의 62% 지점에서 시작해 자신이 내려간 만큼 왼쪽에서 꺾인다 → 꺾임이 45° 스트라이프를 이룬다.
  넓은 창에서는 폭의 55% 간격으로 스트라이프를 반복(`bands`)해 오른쪽 아래까지 채운다. 이 구성은 선이 절대 교차하지 않는다.
- 첫 스트라이프의 빗변(수직 낙차)은 레인 i마다 `128 + 12·i`(#45, `first_diag`; 최소 24, 다음 스트라이프 시작 전에 끝나도록 폭에 따라 상한). 평행한 45° 빗변은 길이가 달라도 교차하지 않고, 지나고 나면 레인 간격이 레인당 12씩 넓어져 선이 부채꼴로 퍼진다. 두 번째 스트라이프부터는 이 넓어진 오프셋(`fanned_offset`)을 기준으로 다시 128 낙차의 계단.
- 레인 수는 `LEAD_LANES(8) + 세션 수 + TRAIL_LANES(6)`로 고정(#45). 창이 커져도 레인은 늘지 않고 스트라이프만 는다. 위쪽 보조 레인 8개(`LEAD_LANES`)는 오른쪽 상단을 채우며, 음수 인덱스라 첫 빗변이 짧다.
- 세션 슬롯 k → 레인 `LEAD_LANES + k`(짝의 두 줄 모두 사용, #31). 세션 칩은 항상 대각선 위(45° 회전)에만 놓인다(#29). 빗변의 중점을 기준으로 짝의 위 레인(짝수 슬롯)은 +18, 아래 레인은 −18만큼 빗변을 따라 어긋난다(`PAIR_STAGGER` 36, #44). 이웃 칩의 수직 거리 = 22/√2 ≈ 16px(짝 안 — 칩 높이 22라 6px 겹침, 참고 영상처럼 의도된 것), 46/√2 ≈ 33px(짝 사이)
- 서브에이전트 칩은 부모 대각선 양옆의 수평 구간에만 놓인다(#36): 오른쪽 수평(대각선 끝 커브 +38px부터)과 왼쪽 수평(대각선 시작 커브 −38px까지)에 번갈아(오른쪽 → 왼쪽 → …) 44px 간격. 화면 밖이나 다음 커브 안쪽으로는 가지 않는다(#22). 서브에이전트는 왼쪽 20% 회피를 적용하지 않고 가장자리 12px만 피한다(#37). 제목 배지는 `$USER`(#15)
- 세션은 실행 환경 그룹별로 묶여 블록을 이루고, 블록 사이에 3행을 비우며 그 행에는 선을 그리지 않는다(#41, #42, #49). 그룹 키: Warp 탭(`warp-tab:<window>-<tab>`; Warp의 상태 DB `warp.sqlite`에서 `terminal_panes.uuid`→`pane_nodes.tab_id`를 `sqlite3 -readonly`로 읽음, 없으면 `warpctrl pane list`, 5초 캐시, #43; **이 경로는 Full Disk Access가 있어야 열린다** — 번들에 권한이 없으면 `authorization denied`로 탭 맵이 통째로 비고 pane별 그룹으로 떨어진다. 터미널은 터미널 앱이 가진 권한을 물려받아 항상 되므로 `--list`로는 재현되지 않는다. 거부는 `File::open`의 `PermissionDenied`로 구분해 상태바에 `NO WARP TABS`로 띄우고, 첫 스냅샷의 1.5초 재시도도 건너뛴다 #67) → 없으면 Warp pane UUID → 터미널 프로그램 → desktop. 세션의 그룹이 바뀌면(탭 매핑이 뒤늦게 잡히거나 pane을 다른 탭으로 옮김) 새 블록의 가장 낮은 빈 슬롯으로 옮겨 붙는다. 같은 탭의 pane들은 붙어 있고, 다른 탭/프로그램 사이만 벌어진다. 블록 안에서 슬롯은 고정: 앞 세션이 사라져도 위로 당기지 않고, 새 세션은 그룹 안 가장 낮은 빈 슬롯을 받는다(#23). 앞 그룹이 커지거나 사라지면 뒤 블록이 옮겨지는데, 칩은 페이드하지 않고 자기 선에 얹힌 채 선과 함께 0.4초 동안 미끄러진다(`Rows`, #49): 새 행의 선은 왼쪽 끝에서부터 그려져 들어오고(칩은 선이 닿을 때 나타남), 살아남은 행은 이전에 그려지던 위치(행 단위, 진행 중이면 소수)에서 새 위치로 보간한다(`lane_params_at`). 짝 위/아래 어긋남도 같이 보간(`session_stagger_at`)
- 테스트 패널(⌘T)의 세션마다 네 줄: 상태 · `PR`(없음 + look 다섯 + `CI`·`OK` 스위치 + `+`·`?` 체인 + `A+`·`A−` 아티팩트, #58·#62·#117·#135·#137) · `LINEAR`(없음 + status) · **`HOST`(없음 + WARP·ORCA·APP·CLOUD, #124)**. 출신은 상태가 아니라 덧붙이는 배지지만, 줄 없이 손으로 만들 길이 없는 건 마찬가지다. 목록은 `host::NAMED` 하나에서 오고 데모 렌더도 같은 걸 쓴다 — 마크가 늘면 양쪽이 같이 는다. 샌드박스 세션은 출신 없이 시작한다(PR·티켓과 같은 규칙: 비워두고 붙여가며 본다). **PR 줄의 조작은 전부 '가장 새 것' 을 가리킨다**(#135): look 다섯과 `CI`·`OK` 는 체인의 끝을 바꾸고, `+` 는 다음 look 으로 하나 잇고, `?` 는 GitHub 이 답하지 않은 번호(#112)를 잇는다. `−` 만 전부 지운다. 전에는 look 을 고르면 체인이 통째로 교체돼서 **여러 개인 세션과 상태가 있는 세션 중 하나만** 만들 수 있었다. 답받은 것과 안 받은 것은 번호와 상한(`MAX_PER_SESSION`)을 함께 쓴다 — 트랜스크립트가 부른 한 묶음을 GitHub 이 답했는지로 가른 것이라서.
- 상태바(30px): 왼쪽 요약(세션/작업/입력 대기/idle 수), 가운데 호버 상세, 오른쪽에 플랜 사용량 배지 → SETTINGS → TEST 버튼. 사용량 배지는 창마다 `5H [▬▬▬░░] 22% ↻2H10M`처럼 이름 + 44×4 프로그레스 바 + 퍼센트 + 리셋 카운트다운으로 그린다(#48, #52). 바의 채움은 팔레트의 패킷 색이라 테마마다 알아서 맞고, 트랙은 잉크 18%. 첫 조회 성공 전에는 안 보이고, 15분 넘게 갱신에 실패하면 바까지 통째로 45%로 흐려진다. 로그인 없는 머신(API 키 사용자)에서는 영영 안 보인다
- 칩은 화면 왼쪽 20%(#30) 안쪽이나 오른쪽 가장자리 밖에 놓이지 않는다. 후보 자리(첫 스트라이프의 대각선 → 다음 스트라이프의 대각선 …) 중 화면 안에 들어오는 첫 자리를 쓴다(#27). 세션이 많으면 아래 레인의 대각선도 화면 안에 있도록 스트라이프 수를 늘린다
- 창 크기 변경 등으로 같은 선 위의 자리(스트라이프)가 바뀌면 옛 자리에서 0.22초 페이드아웃 후 새 자리에서 0.22초 페이드인(#28). 같은 자리 안에서 미끄러지는 것은 애니메이션 없이 따라간다. 자리 키에 레인 번호는 들어가지 않으므로 레인이 바뀌는 것만으로는 페이드하지 않는다(#49)
- 세션 칩 높이 22, 모서리 4, 좌우 패딩 13, 최소 폭 56. 서브 칩 높이 16 (#35: 칩 크기는 줄이지 않는다)
- 라벨: D-DIN Regular(`assets/fonts/D-DIN.ttf`, 바이너리에 `include_bytes!`로 내장)의 글리프 외곽선을 `ttf-parser`로 읽어 채우기 경로로 렌더링(#47, #55) — 45° 회전을 위해 경로로 그린다. `scale`은 캡 높이 = 6px × scale (세션 1.5 → 9px, 서브 1.1 → 6.6px, 제목 2.6 → 15.6px). 커닝(`kern`) 적용. 상태바·패널 등 gpui UI도 같은 서체 — 시작할 때 `ui::register_fonts`가 같은 바이트를 gpui에 등록한다(`theme::UI_FONT = "D-DIN"`, #46, #55) **D-DIN 은 232 코드포인트뿐이고 한글은 0자**라, 한글 라벨은 `glyph_index(c).or(glyph_index('?'))` 의 `?` 로 통째로 떨어지고 있었다 — gpui 가 그리는 패널(⌘K·⌘L·상태바)은 gpui 자체 폴백이 있어 멀쩡했던 탓에 보드만 깨져 보였다. 이제 페이스가 **체인**이다(#119): 글자마다 그 글자를 가진 첫 페이스를 쓰고, D-DIN 이 없는 것만 시스템으로 내려간다 (`AppleSDGothicNeo.ttc` → `Hiragino Sans GB.ttc` → `Apple Symbols.ttf`, 없으면 건너뛰고 끝까지 없으면 종전대로 `?`). **읽지 않고 매핑한다** — 한글 페이스가 55MB 이고 ASCII 뿐인 보드는 그 중 한 페이지도 안 건드린다(체인 전체 resident 비용 약 0.33MB: 10.8 → 11.1MB). **모든 페이스를 같은 캡 높이로** 그린다 — `scale` 이 약속하는 건 캡 높이뿐이고, 그 약속은 어느 페이스에서 온 글자든 지켜야 한다. 텍스트 엔진이라면 em 을 맞추겠지만 여기선 두 값이 몇 % 안에서 일치한다(D-DIN cap/em 0.69, Apple SD Gothic Neo 0.70). 한글은 라틴 캡보다 조금 위로 서고 베이스라인 아래로 조금 내려가는데, 둘 다 보드가 이미 소문자 어센더·디센더로 그리고 있는 범위 안이다. 커닝은 같은 페이스 안의 쌍에만 적용된다(경계를 넘으면 찾을 쌍이 없다).
- 소켓 24×14, 홈 6×6, 분리 시 칩 이동 16, 파형 길이 46, 진폭 6

## 성능(#38)

- **프레임 시계는 움직일 때만 빠르다**(#126): 보드는 vsync 가 아니라 제 시계로 다시 그리는데, 그 시계가 **아무것도 안 움직이는 보드 위에서도 33ms 로 돌고 있었다** — 매 프레임 장면을 통째로 다시 만들고(`chip_draws`·`lay_out`·`build_shapes`) 테셀레이션하고 Metal 에 프레임을 넘긴다. 실측 **15.9% CPU**. 이제 `Board::moving()` 이 **애니메이션만** 보고 33ms / 250ms 를 고른다 — `0.4%` 로 떨어졌다. 250ms 는 멈춤이 아니라 **바닥**이다: 예측이 틀려도 1/4초 늦을 뿐 얼어붙지 않는다. 움직이는 것은 넷뿐이다 — 도착 파도(`comb::wave_over`) · 점멸(`comb::blinks`, 그리는 쪽에 두고 테스트로 묶었다) · 칩의 소켓 애니메이션(`Anim::moving`, **언플러그 타이머 포함** — 아직 안 움직이지만 곧 움직인다) · 회로 뷰의 패킷(레인이 있는 한 안 멈춘다). 나머지는 전부 제자리에서 `cx.notify()` 를 부른다(폴링·키·마우스) — **시계는 아무도 알려주지 않는 것만 맡는다**. 처음엔 `mouse.is_some()` 도 조건에 넣었다가 10.5% 에서 안 내려갔는데, `self.mouse` 는 한 번 설정되면 지워지지 않아 포인터가 창을 한 번만 지나가도 영원히 '움직이는 중' 이 된다. 호버는 이미 `Anim::moving` 과 이벤트가 맡는다.
- 선·라벨·칩 경로는 기하 해시를 키로 테셀레이션 결과를 캐시한다(`render/paint.rs`). 색은 그릴 때 입히므로 알파 애니메이션이 캐시를 깨지 않는다. 패킷(폭 12 미만)은 매 프레임 움직이므로 캐시하지 않는다.
- 화면 갱신은 vsync 대신 33ms 타이머(≈30fps), 세션 폴링은 1초. 측정: 66% → 8% CPU (M-series, 창 980×620).
- 캐시는 정점 예산(32만 정점 ≈ 10MB)으로 제한하고 예산 초과 시 이번 프레임에 안 쓴 항목을 버린다(#40). 메모리: 980×620 93MB, 2560×1440 99MB.
