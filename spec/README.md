# 명세 (#250)

`cargo test` 는 **한 가지 순서**를 본다. 여기 있는 것들은 순서가 정답을 정하는 자리,
그래서 테스트가 끝내 못 보는 자리다 — 폴링 셋이 동시에 날아다니는 동안 손이 보드를
고치고, 워커 셋이 같은 지도를 번갈아 잡고, 시계가 두 번 지나야 비로소 참이 되는 규칙들.
TLC 는 그 **모든 끼어듦**을 다 본다.

```sh
tools/spec.sh      # jar 을 캐시에 한 번 받고, 모든 명세를 검사한다 (몇 초)
```

명세는 코드의 사본이 아니다. **코드에서 규칙이 사는 한 자리**와 짝지어져 있고, 그
짝이 맞는지는 아무도 자동으로 검사해 주지 않는다 — 그래서 모델마다 어느 함수를 비추는지
맨 위에 적혀 있고, 그 함수를 고치면 명세도 같이 고쳐야 한다.

| 모델 | 비추는 코드 | 묻는 것 |
|---|---|---|
| `Polling` | `ui::state::landing` ← `Board::take_polled` | 손으로 바꾼 뒤 도착한 낡은 스냅샷이 **절대** 되돌리지 않는다 (#197) |
| `PrWorkers` | `pr::Shared::claim`·`store`, `pr::ask` | 둘이 같은 PR 을 쥐지 않는다 · `inflight` 와 `seen` 이 서로 어긋나지 않는다 · 아무것도 영영 안 물어본 채로 남지 않는다 (#64, #247) |
| `Presence` | `host::warp::Presence::next` ← `Warp::gone_at` | 한 번 운 나쁜 읽기로는 pane 을 죽이지 않는다 · 모르면 아무 말도 안 한다 · 기다린 뒤 여전히 없으면 놓아 준다 (#186, #192) |

## 기능을 더할 때

1. 그 기능이 **순서에 기대는지** 본다. 스냅샷 → 모델 → 타일 같은 순수 변환이면 명세가 아니라
   `cargo test` 가 맞는 도구다. 스레드·타이머·유예·재시도·세대가 끼면 여기 자리가 있다.
2. 자리가 있으면 **코드부터 FSM 으로** 만든다(#251): 상태마다 이름 하나, 전이는 함수 하나.
   흩어진 불리언 셋은 모델로 옮길 수가 없다 — 옮긴 것이 코드와 같은 물건인지 말할 수 없으니까.
3. 모델을 쓰고 `tools/spec.sh` 를 돌린다. **통과만으로는 부족하다**: 그 규칙을 일부러 깨 보고
   TLC 가 잡는지 확인한다(테스트 가드와 같은 규칙이다). 실제로 해 봤다 —
   `Polling` 에서 세대 가드를 빼면 `NeverUndone` 이, `Presence` 에서 유예를 빼면
   `GoneOnlyAfterTheWait` 가 세 걸음 만에 반례를 내놓는다.
4. 명세가 있는 영역(`pr.rs` 의 워커 풀, `take_polled`, `warp.rs` 의 `gone_at`)을 건드렸으면
   커밋 전에 `tools/spec.sh` 를 돌린다.

## TLC 가 실제로 찾아낸 것

`PrWorkers` 를 처음 쓸 때 `Refs` 를 **집합**으로 두고 "가져갈 수 있는 것 중 아무거나" 로
모델링했다. TLC 가 아홉 걸음짜리 반례를 냈다 — 워커들이 두 개를 영원히 주고받고 세 번째는
한 번도 안 가져간다. 코드는 `wanted` 가 **리스트**이고 `find` 가 **첫 번째**를 집으므로 그
행동을 하지 않는다. 즉 모델이 코드보다 느슨했던 것이고, 모델을 코드에 맞춰 고쳤다.

그 과정에서 드러난 진짜 사실 하나는 명세에 적는 대신 `PrWorkers.tla` 아래에 적어 뒀다:
**이 풀에는 제 공정함이 없다.** 늘 앞엣것을 집으므로, 답을 내려놓자마자 다시 낡을 수 있다면
뒤엣것은 영영 차례가 안 온다. 그렇게 안 되는 이유는 알고리즘이 아니라 **산수**다 — 가장 짧은
신선도가 12초(#247)이고 보드 한 바퀴가 4초쯤이라, 한 PR 이 돌아오기 전에 나머지가 차례를
갖는다. 숫자가 지키는 규칙은 숫자가 있는 자리(`pr::MOVING` 과 그 이웃들)에 두고, 알고리즘의
성질인 척하지 않는다.
